# P9999 登录页

## 页面定位

P9999 是 App 138 的公共登录页，提供两种入口：

- 钉钉环境内自动登录
- 扫码或账号密码登录

## 登录链路

1. 页面初始化时读取 `JA_SYSTEM_DICT` 中的钉钉和回调配置。
2. 若在钉钉容器内，前端向钉钉请求授权码并走 `auto_login`。
3. 若扫码回调带回 `code`，前端走 `code_login`。
4. 前端统一调用页面 On Demand Process `ding_login`。
5. `ding_login` 调用数据库函数 `JA_STS_APEX_DING_LOGIN`，由后者请求外部接口：
   - `AUTO_LOGIN_URL_138`
   - `CODE_LOGIN_URL_138`
6. 第三方钉钉授权入口使用 `P9999_DING_LOGIN_URL`，该值从 `JA_SYSTEM_DICT` 读取：
   - 优先 `DING_LOGIN_URL_138`
   - 其次 `DING_LOGIN_URL`
   - 再用 `BASIC_URL || '/jingjie/open/oauth2/dingtalk'`
   - 最后才使用生产域名作为兜底
7. 若后端返回用户名和密码，页面自动提交 APEX 登录。

## 当前错误提示行为

- 当扫码登录或自动登录失败时，页面顶部会显示明确错误提示。
- `ding_login` 不再把失败结果统一伪装成 `200`。
- 当前默认提示语：
  - 扫码登录失败：`扫码登录失败，钉钉服务暂不可用或当前账号未开通访问权限，请稍后重试或改用账号密码登录`
  - 自动登录失败：`自动登录失败，请改用账号密码登录`
  - 进程异常：`系统异常，请联系管理员或改用账号密码登录`

- P9999 的扫码回调已经能进入 APEX `ding_login`。
- 当前主要故障点在外部接口返回失败时，原页面没有把失败信息展示给用户。
- 2026-05-13 已补齐前端错误展示和后端返回码透传。
- 2026-05-18 已将第三方钉钉授权登录地址从页面硬编码生产域名改为 `JA_SYSTEM_DICT` 驱动；测试环境 `DING_LOGIN_URL_138` 指向 `https://testjing.jasolar.com/i/jingjie/open/oauth2/dingtalk`。
