# P9999 - Login Page

## Purpose

P9999 is the public login page for `f300`.

## Current Behavior

- Uses username/password login only.
- Authentication scheme `STS_LOGIN` is now backed by app-owned `f300` login objects:
  - auth function: `F300_ADMIN_APEX_LOGIN`
  - post-auth process: `F300_ADMIN_LOGIN_SUCCESS_V2`
- Only the `ADMIN` account is allowed to sign in.
- All non-`ADMIN` accounts are rejected at the authentication stage.

## Session Initialization

After a successful `ADMIN` login, the app initializes the session state needed by the `f300` runtime pages, including:

- `USER_TENANT`
- `USER_ID`
- `MPF_USER_ID`
- `USER_NAME`
- `USER_JOB_NUMBER`
- `ROLE_ID`
- `ROLE_CODE`
- `ROLE_LEVEL`
- `APP_ENV`
- `STS_APPKEY`
- `STS_APPSECRET`

## Notes

- `f300` is a sub-platform management backend and no longer initializes or depends on a session-level `SYSTEM_ID` switch state.
- The post-login DB logic is app-owned under `export/file-management-platform@test/f300/db/`.
- The copied login-success flow was cleaned to use `FMP_*` user/role/system tables.
- Verified working login entry in test: `f?p=300:LOGIN:0`.
- The pretty login route `/r/ja_uat/300/login` still shows a separate environment-level submit-path issue and is not yet the verified path.
