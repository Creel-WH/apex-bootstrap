# 上传成功后跳转无效地址排查

## 背景

- 现象：文件上传流程显示上传成功后，页面继续跳转或打开了一个无法访问的地址。
- 目标：定位是前端返回地址、APEX 分支、对话框关闭逻辑，还是后端写入的文件地址有问题。

## 初步排查范围

- 页面：
  - `P133` 文件库
  - `P136` 文件上传对话页
  - `P137` 文件预览页（若上传后误跳此页）
- 数据库对象：
  - `fmp_upload_files_from_dialog_pro`
- 关注点：
  - 上传成功后的分支与关闭动作
  - 成功消息与返回 URL 拼装
  - `file_url / preview_url / content_url` 等字段的写入值

## 待确认

- 具体报错地址是“上传完成后自动跳转的页面地址”无效，还是“上传后点击文件预览时的文件地址”无效。
- 当前先按“上传成功后流程把用户带到了错误页面或错误文件地址”处理。

## 当前排查结论

- `P136` 上传成功后的前端动作只有：
  - 显示“上传成功”提示
  - 关闭对话框
- `P136` 本身没有在成功后主动跳转到 `P137` 或其他外部地址，因此“上传成功后跳错页面”不是由 `P136` 成功回调直接导致。

- 数据库存储侧已排除明显异常：
  - 最近新上传的 `FMP_FILE` 记录 `FILE_URL` 均已写入；
  - 当前值形如 `test/salestool/20260625/820088879143365.png`，是对象 key，不是空值，也不是损坏 URL；
  - 近 3 天上传记录中未发现 `FILE_URL` 为空的情况。

- 预览签名接口已验证可用：
  - 使用当前应用配置的上传服务地址与签名参数，`/download/batchSign` 能正常为新上传对象 key 返回签名地址；
  - 返回的 `proxySignedFileUrl` 可正常下载文件；
  - `kkPreview?sourceUrl=...` 接口也能返回 200。

## 推断

- 当前问题大概率不在 `fmp_upload_files_from_dialog_pro` 的写库逻辑；
- 更可能出在“上传完成后，从 `P133` 打开新文件预览”的页面链路：
  - `P133 -> P137` 传值是否命中了正确 `FILE_ID`
  - `P137` 运行时是否确实使用了当前导出的 `FMP_FILE` 版本
  - 某个具体文件在运行时是否触发了不同于手工验证样本的前端分支

## 处理方案

- 将 `P133` 的文件预览入口从“隐藏项赋值 + 页面提交 + 分支跳转”切换为与重命名/移动一致的 `apex_util.prepare_url(...)` 直跳方案。
- 这样可绕开 `P133_PAGE / P133_FILE_ID` 页面提交链上的时序与状态依赖，直接以当前 `FILE_ID` 打开 `P137`。
