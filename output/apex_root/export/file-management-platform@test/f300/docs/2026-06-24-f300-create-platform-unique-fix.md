# Fix F300 Create Platform Unique Constraint

- Date: `2026-06-24`
- Environment: `file-management-platform@test`
- App: `f300`
- Goal: fix the unique-constraint failure when creating a new platform from `P301`.

## Root Cause

- `FMP_SYSTEM.SYSTEM_ID` and `FMP_SCOPE.SCOPE_ID` use Oracle identity columns.
- A previous `STS_* -> FMP_*` data copy inserted historical IDs directly into `FMP_SYSTEM` and `FMP_SCOPE`.
- The identity backing sequences were not advanced to the copied maximum IDs afterward.
- Result:
  - `FMP_SYSTEM` next generated id was still below the current max row id
  - create mode in `P301` attempted to insert a duplicate primary key
  - Oracle raised `ORA-00001` on `JASOLAR.SYS_C0047980`

## Fix

- Synced live identity generators in test:
  - `ALTER TABLE FMP_SYSTEM MODIFY SYSTEM_ID GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE)`
  - `ALTER TABLE FMP_SCOPE MODIFY SCOPE_ID GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE)`
- Hardened the historical copy script:
  - `db/data/2026-06-17_copy_sts_to_fmp_objects.sql`
  - now resets the `FMP_SYSTEM` and `FMP_SCOPE` identity positions after copying data

## Verification

- Before fix:
  - rollback test insert into `FMP_SYSTEM` reproduced `ORA-00001`
- After fix:
  - rollback test insert into `FMP_SYSTEM` returned new id `44`
  - rollback test insert into `FMP_SCOPE` returned new id `25329`
